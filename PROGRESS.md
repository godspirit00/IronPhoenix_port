# Iron Phoenix native PC port — progress log

## Goal
Run Iron Phoenix (Xbox, XDK 5849, internal name "XBlade", title id 0x53410003) as a native
Windows game with modern rendering (high res / widescreen / high fps).

## Architecture (decided 2026-10-11)
Xbox code is 32-bit x86 -> it runs natively, no CPU emulation.
- `build/ironphoenix.exe` = 32-bit exe, image base 0x10000. `src/reserve.S` + section merging
  (see build.sh) reserve 0x11000-0x4B0000 inside our own image; default.xbe sections are copied
  there at their original VAs. Our code lives above 0x4B0000.
- **Hybrid header page** at 0x10000: XBE header (0..0xBE4) + 'MZ' + e_lfanew=0xC00 + copy of our
  PE NT headers at 0xC00 (Windows/DLLs keep reading PE headers through the module base!).
- Kernel: 145 xboxkrnl imports reimplemented in `src/kernel/*` (thunk table at 0x30b900 is
  filled by xbe_resolve_kernel_imports). Unimplemented ones fall back to weak logging stubs
  generated by `tools/gen_kernel_table.py` -> `src/kernel/ktable.gen.cpp`.
  build.sh fails if an implementation's stdcall arg count mismatches the stub (@N decoration).
  Some Rtl* are forwarded straight to ntdll (binary compatible) — see misc.cpp kNtdllForwards.
- fs: segment: Xbox KPCR fields read via fs:[0x20/0x24/0x28/0x58] and TLS via fs:[4] are
  patched (45 sites, `src/cpu/fs_sites.gen.inc`) into calls to stubs reading an XThreadBlock
  (fake KPCR+ETHREAD) whose pointer is in a Windows TLS slot. SEH (fs:[0]) works natively.
  Xbox TLS: block sits *below* fs:[4]; _tls_index is negative (-(size/4)).
- Timing: XAPI QueryPerformanceCounter is raw rdtsc @733MHz -> hooked to scaled host QPC.
  D3D rdtsc helper at 0x22FAA0 hooked too.
- IRQL >= DISPATCH_LEVEL = global host lock (Xbox code uses it as a single-CPU lock). DPC thread,
  timer thread (also updates KeTickCount), interrupts: ke_fire_interrupt(irq).
- Memory: Xbox physical RAM window 0x80000000 (64MB, retail layout, NV2A instance memory at top
  per MmClaimGpuInstanceMemory). Contiguous allocator in mm.cpp.
- Files: \Device\CdRom0 -> --game dir, \Device\Harddisk0\PartitionN -> --save dir\PartitionN.
- HLE hooks (JMP at function entry, symbols from XbSymbolDatabase -> src/symbols.gen.h):
  input (XInitDevices/XGetDevices/XInput* -> host XInput + keyboard), XMountUtilityDrive,
  XNetStartup/WSAStartup (offline).

### Graphics decision (2026-10-11)
Game makes ~500 calls to 127 D3D functions, almost no inline pushbuffer use. Chosen approach:
**virtual NV2A** — game's own D3D8 lib runs natively; we emulate the GPU (MMIO at 0xFD000000 via
PAGE_NOACCESS + VEH instruction decode; PFIFO/PGRAPH/PCRTC...), porting xemu's
hw/xbox/nv2a (pgraph + OpenGL renderer) out of QEMU. Dirty tracking of guest RAM via
MEM_WRITE_WATCH/GetWriteWatch. Resolution scaling from xemu's surface scale.
Audio (later): DSound pokes APU MMIO 0xFE820000 directly -> HLE DSound (or LLE via xemu APU).

  [--stretch-ui] [--hz N] [--fullscreen] [--novsync] [-vk] [-vf]`

### GPU port details (2026-10-11)
xemu nv2a copied to `src/nv2a/` (pfifo/pgraph/gl/glsl + register blocks). Compat layer in
`src/nv2a/compat/` (nv2a_compat.h = QEMU/glib subset; qemu_win32.c threads/timers; glo_wgl.c =
WGL offscreen contexts; glad GL 4.6 loader in third_party/glad). `nv2a_host.c` replaces xemu's
nv2a.c: MMIO 0xFD000000 trapped (cpu/mmio.cpp VEH decoder; also emulates in/out port I/O),
RAMIN = plain RAM at 0xFD700000, IRQ thread -> ke_fire_interrupt(3), vblank thread 60Hz,
dirty tracking via GetWriteWatch (RAM window allocated MEM_WRITE_WATCH), tcg_enabled()=false
(xemu's KVM path: surfaces downloaded eagerly). Presenter `src/video/present.cpp` (window,
gamma palette shader, Alt+Enter/F11 fullscreen, --scale N internal res, --fullscreen, --novsync).
Edits to xemu files: pbus.c rewritten, display.c uses surface size, pfifo.c sets ready flag,
include paths rewritten (hw/xbox/nv2a/ prefix dropped).
NOTE: python open() defaults to GBK here - always pass encoding='utf-8'.

- [x] (2026-10-17, user report: "random <1 s halts" + "lights flash") STUTTER FIXES:
      * 0.5 s freezes: DSound spins at DISPATCH_LEVEL waiting for a voice-off acknowledged by its ISR,
        while our ISRs needed the same global IRQL lock -> waited for DSound's 0.5 s timeout. ke.cpp now
        has g_dispatch_lock (IRQL>=2) + g_int_lock (IRQL>2). ke_fire_interrupt: TryEnter dispatch lock
